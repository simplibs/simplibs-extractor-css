# ⚙️ `extractor_css/actions` — Pipeline Steps

The `actions` package turns every text step of [`logic`](logic/README_EXTRACTOR_CSS_LOGIC.md) into an `Action` of
[`simplibs-actions`](https://pypi.org/project/simplibs-actions/): the function with its options bound in advance, constructed once and called with the one value that changes — the text. That is what
makes the steps chainable with `>>`, and what lets them be the `steps` of an extractor profile.

```python
from simplibs.extractor_css.actions import StripCssComments, RemoveCssImports

steps = StripCssComments() >> RemoveCssImports()
steps('@import "a.css"; /* c */\na { b: c; }\n')       # -> 'a { b: c; }\n'
```

Actions are **not** exported from `simplibs.extractor_css` itself — they are a domain of their own, imported through `simplibs.extractor_css.actions`, which defines `__all__`. A function and an action are different
kinds of thing and stay visibly different at the import line. **Three actions**, one for every step of `logic` that returns a text.

## How an action is built and called

Each action is generated by `create_action` from its function: the **text** is the *main input*, and **every other parameter** of the function becomes a keyword-only *constructor option* of the same name.

```python
action = StripCssComments(line_comments=True)      # options
action("// c\na { b: c; }\n")                      # main input -> 'a { b: c; }\n'
```

The options and the text are checked by the same annotations as the parameters of the function, and an error raised by the function surfaces unchanged — an action adds no layer of its own.

## A note on one action, not two

SCSS and Less need only the option `line_comments=True`, so there is **no second class** for them. The [presets](README_EXTRACTOR_CSS_PRESETS.md) and the profiles build the two pipelines — one for plain
`.css`, one for the preprocessors — from the same action.

## A note on what has no action

`css_comment_spans` returns **spans**, not a text, so it is not a link of a pipeline that carries text. It stays a function.

### `StripCssComments`

Wraps [`strip_css_comments`](logic/README_EXTRACTOR_CSS_LOGIC.md#strip_css_comments) — takes the comments out of the stylesheet flowing in.

**Constructor options:**
* `line_comments` (*bool*, default `False`): Also remove `// ...` comments (SCSS and Less).
* `keep_license` (*bool*, default `False`): Keep the comments that tools keep (`/*! ... */`, `@license`, `@preserve`).

**Main input:** the text (`str`). **Returns:** `str`.

**Example usage:**
```python
from simplibs.extractor_css.actions import StripCssComments

StripCssComments()("a { b: c; } /* n */\n")                                   # -> 'a { b: c; }\n'
StripCssComments(line_comments=True, keep_license=True)("/*! v */\n// n\na { b: c; }\n")     # -> '/*! v */\na { b: c; }\n'

pipeline = StripCssComments() >> StripCssComments(line_comments=True)         # as steps of a pipeline
```

<details>
<summary>🔍 Under the hood</summary>

```python
StripCssComments = create_action(
    strip_css_comments,
    main_param="text",
    class_name="StripCssComments",
)
```

</details>

### `RemoveCssImports`

Wraps [`remove_css_imports`](logic/README_EXTRACTOR_CSS_LOGIC.md#remove_css_imports) — takes `@import`, `@use` and `@forward` out of the stylesheet flowing in.

**Constructor options:**
* `line_comments` (*bool*, default `False`): Read `// ...` as a comment (SCSS and Less), so an import inside one is left alone.

**Main input:** the text (`str`). **Returns:** `str`.

**Example usage:**
```python
from simplibs.extractor_css.actions import RemoveCssImports

RemoveCssImports()('@import "a.css";\na { b: c; }\n')                          # -> 'a { b: c; }\n'
RemoveCssImports(line_comments=True)('// @import "x";\n@use "y";\na { b: c; }\n')     # -> '// @import "x";\na { b: c; }\n'
```

<details>
<summary>🔍 Under the hood</summary>

```python
RemoveCssImports = create_action(
    remove_css_imports,
    main_param="text",
    class_name="RemoveCssImports",
)
```

</details>

### `CssOutline`

Wraps [`css_outline`](logic/README_EXTRACTOR_CSS_LOGIC.md#css_outline) — turns the stylesheet flowing in into the list of its selectors and at-rules.

**Constructor options:**
* `line_comments` (*bool*, default `False`): Read `// ...` as a comment (SCSS and Less).
* `max_depth` (*int_positive | None*, default `None`): How many levels of nesting to list; `None` lists all.

**Main input:** the text (`str`). **Returns:** `str` — one header per line, indented by depth.

**Example usage:**
```python
from simplibs.extractor_css.actions import CssOutline

CssOutline()("@media print { .a { b: c; } }\n")                  # -> '@media print\n  .a\n'
CssOutline(max_depth=1)("@media print { .a { b: c; } }\n")       # -> '@media print\n'
```

<details>
<summary>🔍 Under the hood</summary>

```python
CssOutline = create_action(
    css_outline,
    main_param="text",
    class_name="CssOutline",
)
```

</details>

> 💡 The outline is a step that **replaces** the text rather than cleaning it, so it is the last link of its pipeline: whatever follows would work on the list of headers, not on the stylesheet.

### Errors of this package

It raises no cards of its own: whatever the wrapped function raises surfaces unchanged (see [the errors of `logic`](logic/README_EXTRACTOR_CSS_LOGIC.md#errors-of-this-package)). A wrong type of a constructor option
or of the text is a `ValidationError`, and a stylesheet that looks damaged is a warning, not an error.
